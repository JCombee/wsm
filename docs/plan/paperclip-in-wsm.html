Paperclip in wsm

Kan Paperclip volledig in de geïsoleerde rootless Podman-sandboxes van wsm draaien, en daar ook zijn werk doen? Ja, als één sandbox per Paperclip-instantie. De server, de database, de plugins en alle agents draaien samen in één werkcontainer. Het board van Paperclip is de preview van die sandbox.

Vorm
Eén sandbox per instantieWe noemen die de hoofdkantoor-sandbox.
Wijzigingen aan wsm
Geen nodigAlles past in fase 1, en geen invariant wordt gebroken.
Uitzonderingen

Binnen die sandbox is er één vertrouwensdomein. Wat Paperclip daar belooft (rollen, goedkeuringen, budgetten), is geen veiligheidsgrens, want elke agent draait als dezelfde gebruiker als de server. De grens is wsm, en die houdt de schade binnen het project.

1 · De kernvraag

Waar ligt de grens?

Paperclip en wsm trekken de grens op een andere plek. Paperclip draait agents normaal zonder sandbox, op de machine van de server. Met een sandbox-provider is de server de vertrouwde kant en de sandbox de onbetrouwbare. wsm gaat ervan uit dat alles in een sandbox vijandig is, en dat alleen de manager, de helper en de host te vertrouwen zijn.

"Paperclip volledig in wsm" zet dus ook de Paperclip-server aan de onbetrouwbare kant.

2 · De keuze

Twee vormen, en maar één kan

Vorm A zet alles in één sandbox. Dat is Paperclips lokale model, in een afgesloten doos.

Vorm B zet de server in sandbox P en elke agent in een eigen sandbox. Dan moet P andere sandboxes kunnen aanmaken, er commando's in draaien en er bestanden uit halen. Dat zijn precies de beheerbevoegdheden die wsm alleen aan de eigenaar geeft.

3 · Het ontwerp

De hoofdkantoor-sandbox

Eén wsm-project per Paperclip-company, met één sandbox die Paperclip draait, bijvoorbeeld acme/hq. De werkcontainer start met het image van Paperclip als hoofdproces. De agents zijn child processes van de server, in dezelfde container. Het board is de preview op app-poort 3100.

4 · In beweging

Een heartbeat, stap voor stap

Een agent werkt in korte runs. Hieronder één run waarin een agent een issue oppakt, een database aanvraagt via de MCP van wsm, en zijn werk lokaal commit. Alleen de pijlen over de groene lijn verlaten de sandbox.

5 · Bouwen

Image en configuratie

Het projectimage moet aan twee lijsten voldoen. wsm vraagt tmux, git, bash, gebruiker 1000 met home /home/agent, en een hoofdproces dat blijft draaien. Paperclip vraagt node 24.11 of nieuwer, de agent-CLI's op PATH, sh, tar en schrijfbare home-, cache- en tmp-mappen. Het entrypoint van Paperclip werkt al zonder root.

Route A: afgeleid van het officiële image advies

Basis
ghcr.io/paperclipai/paperclip:sha-<commit>, publiek, amd64 en arm64.
Voordeel
Het artefact dat Paperclip zelf test. Claude Code, Codex, OpenCode, Gemini CLI en Kimi zitten erin.
Nadeel
Groot: ongeveer 2,9 GB aan dependencies en een provider-pack van ongeveer 2,5 GB, dat we niet gebruiken.
Erbij
tmux, de home van UID 1000 naar /home/agent, en het startscript.

Route B: eigen image met npm te testen

Basis
node:24-trixie-slim plus npm install -g paperclipai@<versie>. Dat pakket bevat de server en embedded-postgres; paperclipai run start alles.
Voordeel
Kleiner, en je kiest zelf de CLI's.
Nadeel
Niet de route die Paperclip test. De spike moet uitzoeken of het werkt en welke versie bij welke commit hoort.
Erbij
Alles.

Schets van de Containerfile, route A, nog niet getest

FROM ghcr.io/paperclipai/paperclip:sha-<volledige commit-sha>

USER root
RUN apt-get update \
 && apt-get install -y --no-install-recommends tmux bash \
 && rm -rf /var/lib/apt/lists/* \
 && usermod --login agent --home /home/agent node \
 && groupmod --new-name agent node \
 && mkdir -p /home/agent && chown 1000:1000 /home/agent

# De build-context van wsm bevat alleen de Containerfile (ADR 0008),
# dus het startscript staat inline.
RUN cat > /usr/local/bin/wsm-paperclip <<'EOF'
#!/bin/sh
set -eu
: "${WSM_PREVIEW_URL:?het project heeft --app-port 3100 en een preview-domein nodig}"
export PAPERCLIP_HOME="$HOME/.paperclip"
export PAPERCLIP_INSTANCE_ID="$WSM_SANDBOX"
inst="$PAPERCLIP_HOME/instances/$PAPERCLIP_INSTANCE_ID"
export PAPERCLIP_CONFIG="$inst/config.json"
export HOST=0.0.0.0 PORT=3100
export PAPERCLIP_DEPLOYMENT_MODE=authenticated PAPERCLIP_DEPLOYMENT_EXPOSURE=private
export PAPERCLIP_PUBLIC_URL="${WSM_PREVIEW_URL%/}"
export PAPERCLIP_API_URL="http://127.0.0.1:3100"
export PAPERCLIP_TELEMETRY_DISABLED=1 DO_NOT_TRACK=1
export PAPERCLIP_DISABLE_CWD_ENV_FILE=true
umask 077
mkdir -p "$inst"
if [ ! -f "$inst/.env" ]; then
  node -e 'const r=()=>require("crypto").randomBytes(32).toString("hex");
    console.log("BETTER_AUTH_SECRET="+r()+"\nPAPERCLIP_TOOL_ACTION_SIGNING_SECRET="+r())' > "$inst/.env"
fi
# Houd de sandbox in leven als Paperclip herstart, en geef een stop door.
trap 'kill -TERM "$pid" 2>/dev/null; wait "$pid"; exit 0' TERM INT
while :; do
  "$@" & pid=$!
  wait "$pid" || true
  sleep 5
done
EOF
RUN chmod 0755 /usr/local/bin/wsm-paperclip

USER 1000:1000
WORKDIR /workspace
# wsm start de container al met --init, dus tini is hier niet nodig.
ENTRYPOINT ["/usr/local/bin/wsm-paperclip"]
CMD ["node", "/app/server/dist-runtime/index.mjs"]

Het project aanmaken. Kies de limieten ruim, want ze liggen vast na project create. De standaard (2 CPU's, 2 GiB, 1024 pids) is te krap voor een server, een database en meerdere agents tegelijk.

wsm project create --slug acme \
  --containerfile examples/paperclip/Containerfile \
  --repo git@github.com:acme/product.git --branch main \
  --cpus 4 --memory 8g --pids 4096 --app-port 3100
wsm project key acme                            # read-only deploy key toevoegen
wsm project block set acme mariadb --tag 11.8   # optioneel, voor de app van de agents
wsm sandbox create acme/hq
wsm sandbox start acme/hq
wsm shell acme/hq   # eenmalig: paperclipai auth bootstrap-ceo, claude login, codex login

  • Nooit twee processen op één datamap. Twee Paperclip-processen op dezelfde datamap betekent corrupte PostgreSQL-data. De eigen PAPERCLIP_INSTANCE_ID per sandbox voorkomt dat.
  • De back-ups van Paperclip zijn geen echte back-up. Ze staan op hetzelfde volume. Een echte back-up is een export van het home-volume buiten de sandbox om, en dat is handwerk.
  • Dezelfde naam, dezelfde data. Na het verwijderen van acme/hq vindt een nieuwe sandbox met dezelfde naam de Paperclip-data terug, maar niet de code en niet de worktrees.
  • Plugins zijn per project. Paperclip installeert ze in ~/.paperclip/plugins, niet per instantie. Alle sandboxes van het project delen die map.

8 · Toegang

Inloggen en origins

Het board staat achter twee lagen: eerst de passkey van wsm, daarna de eigen login van Paperclip. De cookies van wsm en van Paperclip staan elk op hun eigen origin.

  • Wie het eerst claimt, wint. Zolang er geen instance-admin is, wint de eerste ingelogde browser die het board claimt. Een agent kan via loopback ook een account aanmaken. Draai daarom direct na de eerste start paperclipai auth bootstrap-ceo in wsm shell, vóórdat er agents draaien, en zet daarna PAPERCLIP_AUTH_DISABLE_SIGN_UP=true.
  • Cookie tossing. Een andere preview-app kan een cookie voor het hele preview-domein zetten, en Paperclip ontvangt die (ADR 0017, punt 8). Dat is geaccepteerd zolang er één eigenaar is. Een apart registreerbaar preview-domein blijft het advies.
  • Invariant 11 gaat over het wsm-dashboard. Paperclip toont agent-content op zijn eigen preview-origin, met HTML-artefacten in een sandboxed iframe. Dat raakt het dashboard niet.

9 · Wat de grens wel en niet doet

Vertrouwen binnen de sandbox

Paperclip zegt het zelf: binnen een sandbox beschermt het niets, en lokale adapters draaien zonder sandbox. In dit ontwerp betekent dat: wat één agent kan, kunnen alle agents. Ook het startscript of de server zelf vormt geen grens.

  • Eén company per project. Wie de instantie raakt, raakt elke company erin.
  • Budgetten zijn te omzeilen. Een agent kan de database aanpassen: PostgreSQL luistert op loopback met de vaste login paperclip/paperclip. Zet daarom een bestedingslimiet bij de LLM-aanbieder.
  • Run-sleutels zijn na te maken. Agents erven BETTER_AUTH_SECRET uit de omgeving van de server, en Paperclip tekent de run-sleutels daarmee. Paperclip haalt alleen de PAPERCLIP_*-variabelen weg.
  • Exfiltratie is mogelijk. Het internet staat open, dus een geïnjecteerde agent kan data naar buiten sturen. Dat is een bekende kanttekening in de eisen.
  • Vijandige invoer hoort in een eigen project. Externe PR's en tickets horen in een eigen wsm-project met een eigen Paperclip, zonder waardevolle credentials (U2).

10 · Grenzen van het ontwerp

Wat niet kan, en waarom

Negen dingen die Paperclip kan of wil, maar die binnen de regels van wsm niet lukken. Bij elk punt staat waarom en waar het botst. Oplossingen zijn bewust nog niet onderzocht.

botst met invarianten ontwerp of eigenschap fase 1, al gepland
U1

Paperclip als orkestrator van andere sandboxes

botst met invarianten
Wat Paperclip wil
Runs elders draaien, via een ssh-omgeving, een sandbox-provider (Daytona, E2B, Kubernetes …) of de Runner. Een provider maakt sandboxes, draait er commando's in en synct bestanden.
Waarom niet
Sandboxes maakt alleen de eigenaar. De MCP heeft geen beheertools, en in een sandbox komt geen Podman-socket. Verkeer tussen sandboxes is dicht, en sandboxes hebben geen sshd.

aanname 4 · invariant 1, 2 · ADR 0001, 0002, 0005

U2

Insluiting van vijandige invoer

volgt uit U1
Wat Paperclip wil
De preset low_trust_review voor externe PR's en tickets. Die run start alleen met de sandbox-driver en isolated_workspace.
Waarom niet
Er is geen sandbox-driver, dus zulke runs weigeren te starten. De insluiting is dan die van wsm, per project.

doc/LOW-TRUST-PRESETS.md · U1

U3

Scheiding tussen agents en companies

eigenschap van Paperclip
Wat Paperclip biedt
Rollen, goedkeuringen, budgetten, data per company en sleutels per agent.
Waarom geen grens
Alles draait als UID 1000 in één container. Elke agent kan de database, de master key, .env en het serverproces lezen of aanpassen. PostgreSQL luistert op loopback met de vaste login paperclip/paperclip. Elke agent erft BETTER_AUTH_SECRET, en daarmee tekent hij zelf run-sleutels.

SANDBOX-REQUIREMENTS.md · docs/agents-runtime.md §9 · server/src/agent-auth-jwt.ts

U4

Een wsm-identiteit per agent

ontwerp van wsm
Wat je zou willen
Agent A krijgt wel een database, agent B niet, en de audit log toont welke agent wat deed.
Waarom niet
De identiteit komt alleen uit het MCP-token per sandbox, en alle agents erven dat. Grants gelden per sandbox, netwerktoegang per project-UID.

invariant 2 · ADR 0001, 0012, 0014

U5

Code naar buiten: push, PR's, merges

bewust · fase 2
Wat Paperclip wil
Agents die branches pushen en PR's openen en mergen, met gh en een GitHub-token als secret.
Waarom niet
In de sandbox staan geen git-credentials. Code gaat alleen als bundle naar buiten, via de manager, met review en hersigneren. Dat is fase 2.

eisen "Git, review en signing" · ADR 0009, 0010 · TestNoCredentialsInSandbox

U6

Inkomende webhooks en chatkoppelingen

ontwerp van wsm
Wat Paperclip wil
Webhooks voor Slack, Telegram, Teams en GitHub, voor e-mail, spraak en plugins, en routines die van buiten worden aangeroepen.
Waarom niet
De enige weg naar binnen is de preview. Zonder wsm-cookie krijgt een verzoek een redirect of een 401, en een externe dienst heeft geen passkey.
Wat wel werkt
Discord, want Paperclip houdt daarvoor zelf een uitgaande gateway-verbinding open. Waarschijnlijk ook iMessage via Photon.

ADR 0017 · invariant 10 · server/src/routes/chat-channels.ts

U7

Previews van wat de agents bouwen

fase-1-beperking
Wat Paperclip wil
Dev-servers per workspace, gelinkt via expose.urlTemplate.
Waarom niet
Eén app-poort per project en één preview per sandbox. Die poort is hier het board. De app-poort ligt vast bij project create.

ADR 0017 punt 2 · docs/dashboard.md §5

U8

Rechten of containers in de sandbox

botst met invarianten
Wat Paperclip wil
Tailscale (bind=tailnet), Docker- en Podman-flows, de eigen Bubblewrap-opsluiting per run (filesystemScope), en software installeren tijdens het draaien.
Waarom niet
TUN en NET_ADMIN zijn weg door cap-drop ALL. Er is geen container-runtime en geen socket. Bubblewrap vraagt een geneste user namespace en een nieuwe /proc, en dat weigert de container waarschijnlijk. Er is geen root in de container. Een tweede inkomend pad hoort er niet.

invariant 1, 9 · plan 3.4 · ADR 0017

U9

Paperclip bijwerken

fase-1-beperking
Wat Paperclip wil
Vaak nieuwe versies (CalVer, bijv. v2026.1023.0), zonder werk te verliezen.
Waarom niet
Een project, en dus zijn Containerfile, is na het aanmaken niet te wijzigen. Bestaande sandboxes houden hun image, en sandboxes opnieuw aanmaken met behoud van code (aanname 9) is nog niet gebouwd.

ADR 0008 punt 8 · docs/guide/images.md · aanname 9

11 · Binnen het stramien

Zo pakken we het op

  1. Spike spikes/05-paperclip/

    Wegwerpcode met een FINDINGS.md, op een wegwerp-VM van debian-13-public, met het gescripte nepmodel en nooit met echte sleutels. Klaar als:

    • het image bouwt via wsm project create --containerfile, met alleen de Containerfile als context;
    • Paperclip start als 1000:1000 zonder capabilities, en PostgreSQL draait binnen de pids- en geheugenlimieten;
    • het board werkt via de preview, met login en live updates, en is zonder wsm-login onbereikbaar;
    • een claude_local-heartbeat draait in een worktree, roept de API aan via 127.0.0.1 en schakelt via de MCP MariaDB in;
    • een tweede sandbox van hetzelfde project draait een eigen instantie;
    • stop/start en verwijderen plus opnieuw aanmaken gedragen zich zoals de tabel in §7;
    • er gaat geen verkeer naar telemetry.paperclip.ing;
    • de server leest geen .env uit /workspace;
    • het geheugen, de pids en de schijf per gelijktijdige run zijn gemeten.

  2. ADR, voorbeeld en docs

    Een ADR, bijvoorbeeld "Paperclip in a sandbox", examples/paperclip/Containerfile en een pagina in de docs.

  3. Isolatietests met het Paperclip-image

    De bestaande tests dekken de grenzen al: TestPreview, TestOtherProjectPreviewPort, TestManagerAPINotReachable, TestNoPodmanSocketInSandbox en TestContainerHardening. Een run met dit image laat zien dat ze ook hier gelden.

  4. De uitzonderingen als input

    U1 tot en met U9 zijn input voor besluiten in fase 2 en later. Nu bouwen we er niets voor.
